All Commands & Options

  • View as Markdown
  • Open in ChatGPT
  • Open in Claude

The command comes from the npm package @rapidoc/cli. In a project that has it installed, run it as npx rapidoc <command> or through the npm run scripts. Without it, run npx @rapidoc/cli <command>: npx rapidoc would look for the npm package rapidoc, the <rapi-doc> web component, which has no command.

Command Does
init [dir] Scaffolds a portal in dir (default: the current folder), using the OpenAPI files already there.
dev [dir] Starts the dev server with live reload on http://localhost:4321.
build [dir] Builds the static portal into dist/.
serve [dist] Serves a built portal, with sign-in and access rules (rapidoc serve). Default folder dist.
preview <spec> Shows one spec (a file or URL) in <rapi-doc> on http://localhost:4000, reloading when a file in its folder changes (preview).
mock [dir | spec...] Mock server for a portal’s APIs, a folder of specs, or spec files (paths or URLs), each under /<api id> (Mock Server).
validate [spec | dir] Validates one OpenAPI spec (a file or URL), or every OpenAPI spec and Arazzo spec in a portal (validate).
lint [spec | dir] Checks what a spec needs to make a good portal: operationIds, summaries, examples, security, declared tags (lint).
bundle <spec> Writes a spec split over several files as one: other-file $refs become components (bundle).
pdf <spec> Writes the API reference of a spec as a PDF (pdf). Needs rapipdf.
mcp export <spec> Writes an MCP server project for the spec (mcp).
mcp serve <spec> Runs that MCP server over stdio, without writing files.
migrate [--from <src>] Writes rapidoc.config.yaml from a zudoku or redocly project (found in the folder when --from is left out; Migrating).
doctor [dir] Checks Node, the packages’ versions, the portal config and the browser bundle; --format json for bug reports.
completion <zsh | bash | fish> Prints a completion script for the shell (Shell completion).
help [command] Shows help, or one command’s options and examples (same as rapidoc <command> --help).
--version, -v Shows the version.

Options and arguments can come in any order (rapidoc build --out-dir public ./portal). A misspelled command or option is an error with a suggestion (Unknown option --outdir. Did you mean --out-dir?).

Options

Section titled “Options”
Option Commands Meaning
--out-dir <path> build Output folder. Default dist.
--port <number> dev, serve, mock, preview dev: default 4321; serve: $PORT or 8080; mock: 4010; preview: 4000.
--host <host> serve, mock, preview Address to listen on. Default $HOST (serve), localhost (preview), else 0.0.0.0.
--open dev, preview Open the page in the browser.
--theme <name> preview <rapi-doc> theme.
--mount-path <path> serve Path requests arrive under, when a proxy strips part of the portal’s path. Default $RAPIDOC_MOUNT_PATH, else the path of site.url.
--issuer <url> mock OpenID Connect issuer whose tokens are accepted. Default $RAPIDOC_MOCK_ISSUER.
--audience <id> mock Audience tokens must be issued for. Default $RAPIDOC_MOCK_AUDIENCE.
--seed <number> mock Seed for generated data. Default 1.
--mock-config <file> mock, lint With --stateful: your corrections to what the mock worked out. Default: mock.config.yaml beside the spec.
--delay <ms> mock Wait this long before every API response, to see loading states in a client. Default 0.
--stream-interval <ms> mock Gap between the items of a streamed response (OpenAPI 3.2 itemSchema). Default 300.
--stateful mock Keep state: creates, updates and deletes change stored records that reads and lists return, seeded from the spec.
--rows <number> mock With --stateful: seed records per resource. Default 10.
--debug dev, build Keep the temporary build workspace and print its path.
--title <title> init Site title.
--spec <file> init An OpenAPI file to include; repeat for more. Default: every one found in the folder.
--starter-spec init Use the starter spec instead of the OpenAPI files found.
--force, -f init Overwrite existing files (in a terminal, lists them and asks first).
--no-install init Skip npm install.
--format <format> validate, lint, doctor, bundle validate, lint, doctor: pretty (default), json, or sarif (validate, lint). bundle: yaml or json (default: by the output file’s extension).
--strict validate, lint Fail on warnings too.
--rule <name>=<severity> lint A rule’s severity: error, warn or off; repeatable.
--rules lint List the rules and their defaults.
--stateful lint Also report what the stateful mock had to assume or could not map.
--remote validate, lint, mcp, bundle Also fetch remote specs and remote $refs.
--output <file>, -o bundle, pdf bundle: write here instead of stdout. pdf: default the spec’s name with .pdf.
--dereference bundle Inline every $ref, in-file ones too.
--no-validate bundle Don’t check the result against the OpenAPI Specification.
--api <id> bundle, pdf The spec of this API from rapidoc.config.*, instead of a file.
--title <text>, --footer <text> pdf Cover title (default API Reference) and page footer.
--schema-style <style> pdf object (default) or table.
--examples, --api-list pdf Add request and response examples; add a closing list of every operation.
--no-info, --no-toc, --no-security, --no-api-details, --no-sort-tags pdf Leave out the cover, the table of contents, the security schemes or the operations; keep the tags in the spec’s order.
--primary-color <color>, --alternate-color <color> pdf The PDF’s two colors (default #b44646, #005b96).
--labels <file>, --font <file>, --mono-font <file> pdf Labels to replace (JSON), and fonts in place of Roboto and Roboto Mono.
--out-dir <path> mcp export Where to write the project. Default mcp-server.
--force, -f mcp export Write into a folder that isn’t empty.
--arazzo <file> mcp An Arazzo spec whose workflows become tools too.
--server-name <name> mcp The MCP server’s name. Default: from the API title.
--base-url <url> mcp serve Call the API here instead of the spec’s server (for example rapidoc mock).
--help, -h all Show the command’s help instead of running it.
--quiet, -q all Print errors and warnings only.
--yes, -y all Don’t ask anything: take the default answer to every question.

Questions

Section titled “Questions”

In a terminal, commands ask for what their options don’t say, and rapidoc alone shows a menu of the common commands. When the output is piped, CI is set, or --yes is given, they never ask: they use the defaults, or stop and name the option to pass. Every question has an option, so any run can be scripted.

Command Asks Option that answers it
init The site title, which of the OpenAPI files found to include, whether to run npm install. Then prints the command that does the same without questions. --title, --spec / --starter-spec, --no-install
init --force Whether to replace the existing files it lists. --yes
migrate Which project to migrate, when --from is left out (it looks for redocly.yaml and zudoku.config.*); whether to replace an existing rapidoc.config.yaml. --from, --yes
dev, serve, mock Whether to use the next free port when the port is taken. Without a terminal, serve and mock stop (dev moves to a free port by itself). --port, --yes

Ctrl+C on a question cancels the command (exit code 130).

Output and exit codes

Section titled “Output and exit codes”

On a terminal the CLI prints icons; when its output is piped or NO_COLOR is set, it prints plain text, with error: and warning: in front of problems. Errors and warnings go to stderr, everything else to stdout.

Exit code Means
0 Success.
1 A problem in the input: an invalid spec or config, a failed build, a missing package.
2 A wrong command line: an unknown command or option, a missing or malformed value.
130 Cancelled at a question (Ctrl+C).

Which packages each command needs

Section titled “Which packages each command needs”

The CLI loads the other packages only when a command needs them:

Command Needs
init, validate <spec>, lint <spec> @rapidoc/cli only
dev, build, migrate, validate and lint of a portal folder @rapidoc/portal
serve @rapidoc/server
mock @rapidoc/mock (and @rapidoc/portal for a portal folder)
preview, bundle <spec>, mcp export, doctor @rapidoc/cli only
pdf rapipdf (and @rapidoc/portal with --api)
bundle --api @rapidoc/portal
mcp serve @modelcontextprotocol/sdk

Shell completion

Section titled “Shell completion”

rapidoc completion <shell> prints a script that completes commands, options, their values (--format pretty|json|sarif, mcp export|serve) and file names. It is generated from the commands themselves, so it matches the installed version; regenerate it after updating.

With npx instead of a global install, use npx rapidoc completion zsh once to write the file; eval on every shell start would run npx each time.
