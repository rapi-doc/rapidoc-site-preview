CSS parts

Section titled “CSS parts”

Style the inside of the element from your page with rapi-doc::part(name).

Navigation Sidebar

Parts for customizing the sidebar navigation panel, filter inputs, and route links.

PartElementDescription
section-navbar<nav>Outer navigation sidebar container.
section-navbar-header<div>Header wrapper container inside the sidebar encapsulating the nav logo slot and filter search container.
section-navbar-logo<slot>Slot container for the brand logo or custom header inside the navigation bar.
btn-navbar<button>Mobile hamburger toggle button to open or collapse the navigation sidebar.
section-navbar-search<div>Container wrapping the filter search input inside the navigation sidebar.
textbox-nav-filter<input>Text input element used for real-time search filtering in the sidebar.
btn-clear-filter<button>Clear button inside the sidebar search input.
section-navbar-scroll<div>Scrollable inner container holding all tags, endpoints, and markdown headings.
section-navbar-item<div>Base part applied to every clickable item in the navigation sidebar.
section-navbar-overview<div>Sidebar item pointing to the API Overview section.
section-navbar-servers<div>Sidebar item pointing to the API Servers section.
section-navbar-auth<div>Sidebar item pointing to the Authentication section.
section-navbar-operations-top<div>Sidebar item pointing to the top of the operations list.
section-navbar-tag<div>Sidebar item representing an OpenAPI tag heading.
section-navbar-path<div>Sidebar item representing an individual endpoint operation (e.g., GET /users).
section-navbar-active-item<div>Added to the sidebar item of the section in view (operation, tag, overview, servers, authentication), and moved as the reader navigates. Style it to highlight the whole active row, e.g. rapi-doc::part(section-navbar-active-item) { background-color: #E2000F; color: #fff; }.

Headings

Every heading RapiDoc generates (not headings inside markdown descriptions) carries these parts, so one rule can style a whole level. Outline: API title h1; servers, authentication, tag groups and tags h2; operations h3; Request/Response h4; parameter and request-body labels h5.

PartElementDescription
heading<h1>-<h6>Any heading generated by RapiDoc.
heading-1<h1>Level 1: the API title.
heading-2<h2>Level 2: servers, authentication, tag groups, tags, component groups, and the tag label above an operation in focused mode.
heading-3<h3>Level 3: operation summaries, server variables, OAuth flows, and component names.
heading-4<h4>Level 4: Request, Response, Code samples, and Callbacks labels.
heading-5<h5>Level 5: parameter, request body, and response header labels; callback names.
heading-6<h6>Level 6: Callback request and Callback response labels.

btn-outline<button>Outlined secondary buttons.
btn-clear<button>Button to clear request parameter fields.
btn-clear-response<button>Button to clear returned response data.

btn-search<button>Search submit button in filter dialogues and headers.
btn-response-status<button>HTTP response status code selector buttons (e.g., 200, 400, 404).
btn-selected-response-status<button>The currently active HTTP response status button.

Parameter Lists

Request parameters, request-body form fields, response headers, and server variables. Each list is a grid; every parameter is a subgrid row, so columns line up across rows.

PartElementDescription
param-list<ul>The list; a three-column grid (label, input, constraints). Stacks into one column on narrow widths.
param<li>One parameter; draws its own full-width border. Has the `deprecated` class when deprecated.
param-label<div>First column: name and type.
param-name<div>Parameter name, with the required marker and deprecated icon.
param-type<div>Parameter type or format.
param-input<div>Try-it input (only with `allow-try="true"`, plus object form fields and server variables). Spans both right-hand columns when there are no constraints.
param-constraint<dl>Constraints as label/value pairs (Default, Pattern, Limits, Allowed, or a response header Example). The labels share one column, so all values start at the same place.
param-constraint-label<dt>A constraint label ("Default:", "Pattern:", "Limits:", "Allowed:").
param-details<div>Description and examples, under the input and constraints.
param-example-list<ul>Long-format examples (with a summary or description); one entry per example, each with a thin left rule.
value-list<div>A label with a wrapping list of values (Allowed values, short-format Examples). Wrapped lines line up under the first value.
value-list-label<span>The label of a value list ("Allowed:", "Examples:").
value-list-items<ul>The values; separators between them are drawn in CSS and stay at the end of a line.
