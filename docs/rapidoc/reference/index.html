Every attribute of <rapi-doc>, read from the element’s own source, so this page matches the release it is built from. Set one on the element in HTML, or change it at runtime with setAttribute. The rest of the reference: Methods, Events, Slots, Spec Extensions and CSS Parts & Variables.

Spec & Content Attributes 9

AttributeDescription and allowed valuesDefault
spec-url
URL of the OpenAPI specification file (JSON or YAML) to load and render.
(empty)
sort-tags

truefalse

Sorts tags in alphabetical order. When set to "false", preserves the tag order defined in the OpenAPI specification.
false
sort-schemas

truefalse

Sorts component schemas alphabetically. When set to "false", preserves the order defined in the spec. Note: Only has an effect if render-style="focused" and show-components="true".
false
sort-endpoints-by

pathmethodsummarynone

Sorts endpoints within each tag group by path, HTTP method, or summary. 'none' leaves the sort order unmodified.
ⓘ This is a static initialization attribute. It will not have any effect if modified using JavaScript after the spec is rendered.
See it running →		path
show-unused-tags

truefalse

Shows tags that no operation uses, as long as they have a description, so a tag can hold a guide or concepts section (written in markdown) next to the operations. Each such tag gets a section and a sidebar link. When "false", tags without operations are left out, except those the spec lists in x-tagGroups, which show either way. Either way, an OpenAPI 3.2 tag that is the parent of other tags is drawn as their group's heading, not as a section, and a tag whose kind is not nav never gets one.
ⓘ This is a static initialization attribute. It will not have any effect if modified using JavaScript after the spec is rendered.
false
filter-operations
Which operations to show: a space- or comma-separated list of terms. An operation is shown when it matches any include term (every one is, without one) and no ! term. A term is an operationId (getPetById), a method and path (GET /pet/{petId}), a path for all its methods, a path glob (/pet/**; * is one segment, ** any number), tag:store, badge:Beta (an x-badges label, or an OpenAPI 3.2 tag of kind: badge) or deprecated; ! before a term leaves out what it matches (!badge:Internal). Shown operations keep the order of the first term they match, so a list of operationIds shows them in that order (unless sort-endpoints-by is set).
See it running →		(empty)
match-pathsDeprecated
[REMOVED] Use filter-operations: a path glob (/pet/**), a method and path, or operationIds.
—
match-typeDeprecated

includesregex

[REMOVED] filter-operations matches exact terms and path globs, not substrings or regular expressions.
includes
remove-endpoints-with-badge-label-asDeprecated
[REMOVED] Use filter-operations="!badge:Beta".
—

Layout & Scrolling Attributes 4

AttributeDescription and allowed valuesDefault
render-style

readviewfocused

Controls the overall documentation presentation layout. Three distinct modes are supported:
  • view: Optimized for interactive exploration with collapsible operations | Example
  • read: Continuous narrative page layout, ideal for reading through API specifications from top to bottom | Example
  • focused: Displays a single endpoint at a time with a dedicated sidebar, ideal for large enterprise schemas | Example
read
layout

rowcolumn

Controls the multi-column orientation of request parameters and response panels on desktop screens (>768px). In 'row' layout, request and response sections sit side-by-side; in 'column' layout, they stack vertically. Defaults to 'column' when render-style is 'read' or 'focused', and 'row' when render-style is 'view'.
column (read, focused) / row (view)
response-area-height
Allowed: Any valid CSS height value (e.g. 400px, 50%, 60vh).
Controls the vertical height of the interactive response payload viewer.
400px
scroll-offset
Allowed: A number of pixels (e.g. 96).
With auto-height="true", where the page scrolls instead of RapiDoc, this is the height of a sticky or fixed page header. Navigation scrolls a section to just below it, and the active navigation item ignores sections hidden under it. When not set, RapiDoc uses the scroll root's scroll-padding-top, so a page that already sets it needs no extra configuration.
(scroll-padding-top of the page)

Sidebar & Navigation Attributes 11

AttributeDescription and allowed valuesDefault
show-side-nav

truefalsefloating

The navigation sidebar (read and focused modes). true docks it beside the content on wide layouts and turns it into a menu button with a slide-over menu when the element is narrower than 768px; floating uses the menu button and slide-over menu at every width, so the content takes the whole width; false shows no sidebar.
true
show-method-in-nav-bar

falseas-plain-textas-colored-textas-colored-block

Displays HTTP methods (GET, POST, etc.) alongside endpoint items in the navigation sidebar. Ensure sufficient contrast if customizing nav-bg-color.
See it running →		false
show-badges-in-nav-bar

dotfalse

Marks sidebar items whose operation shows a badge (x-badges, or an OpenAPI 3.2 tag of kind: badge) with a small dot in the first badge's color; its tooltip and accessible label list the badges. Badges with color: none are left out. The dot's shape and size can be styled with the nav-badge-dot CSS part.
See it running →		dot
use-path-in-nav-bar

truefalse

Displays raw API URL paths in the navigation bar instead of operation summaries.
NOTE: Setting this to true displays the path only. To display the HTTP method alongside the path, also configure show-method-in-nav-bar.
See it running →		false
nav-item-spacing

defaultcompactrelaxed

Controls vertical density and padding between sidebar navigation items.
See it running →		default

ellipsiswrap

Controls text truncation behavior for long endpoint paths and operation summaries in the navigation sidebar. When set to ellipsis (default), long paths truncate with a clean ellipsis. When set to wrap, long items wrap across multiple lines without clipping.
ellipsis
info-description-headings-in-navbar

truefalse

Extracts Markdown headings (H1 and H2) from the specification's info description and adds them to the sidebar navigation menu (read mode only).

When set to "true", automatically updates the browser's URL address hash as the user scrolls through or clicks on different sections.
true
goto-path
Target endpoint location to navigate to automatically after the specification finishes loading. Must be provided in the format of {method}-{path} (e.g., to focus on GET /user/login, provide get-/user/login).

left-bar

Try & Servers Attributes 7

AttributeDescription and allowed valuesDefault
allow-try

truefalse(or filter-operations terms, e.g. !deprecated)

Enables the interactive "TRY" console allowing users to test live API calls directly from their browser. Besides true and false, it takes the terms of filter-operations to turn Try on only for the operations they select: !deprecated !tag:pending-implementation keeps it off for deprecated operations and those tagged pending-implementation. The others keep their request documentation and show a disabled TRY DISABLED button. The Authentication section stays usable unless it is false.
See it running →		true
show-curl-before-try

truefalse

When set to true, generates and displays copyable cURL commands directly within the endpoint documentation prior to clicking "TRY".
See it running →		false
fill-request-fields-with-example

truefalse

Pre-populates interactive request parameter inputs and request body fields using example values defined in the OpenAPI spec.
true
allow-server-selection

truefalse

Enables the dropdown allowing users to switch between target servers declared in the OpenAPI spec.
true

Custom API server base URL. Overrides the servers array defined in the OpenAPI specification. Particularly useful when sharing a single spec across development, staging, and production environments.

omitsame-origininclude

Authentication Attributes 8

AttributeDescription and allowed valuesDefault
allow-authentication

truefalse

Controls the display of interactive authentication controls (HTTP Basic, Bearer Token, API Key, OAuth2). Disable to hide authentication dialogs when using hardcoded or pre-authenticated API keys.
true
persist-auth

truefalse

Keeps API keys, bearer tokens and OAuth access tokens in localStorage across page reloads; an OAuth token is dropped once it expires. Basic credentials and OAuth client secrets are never stored.
false
api-key-name
Name of the header or query parameter used when transmitting the API key in interactive console requests.
(empty)
api-key-location

headerquery

Specifies whether the API key is passed as an HTTP request header or query parameter.
header
api-key-value
Pre-configured API key value sent during interactive console requests. Can also be set or overwritten directly in the UI.
(empty)
oauth-receiver
Relative or absolute path to the OAuth receiver HTML file for handling authorization redirection callbacks.
oauth-receiver.html
additional-authorize-params
Custom query parameters appended to the OAuth2 authorization URL query string (e.g. proxy launch tokens, prompt, audience).

Supported Formats:
  • JSON String (recommended for HTML attributes):
    additional-authorize-params='{"launch": "xyz123", "prompt": "consent"}'
  • URL Query String:
    additional-authorize-params="launch=xyz123&prompt=consent"
  • JavaScript Object (via property):
    rapidocEl.additionalAuthorizeParams = { launch: 'xyz123', prompt: 'consent' };
(empty)
additional-token-params
Custom parameters included in the POST request body sent to the OAuth2 token endpoint (e.g. custom proxy parameters, resource, audience).

Supported Formats:
  • JSON String (recommended for HTML attributes):
    additional-token-params='{"audience": "https://api.example.com", "resource": "urn:my:api"}'
  • URL-Encoded String:
    additional-token-params="audience=https%3A%2F%2Fapi.example.com"
  • JavaScript Object (via property):
    rapidocEl.additionalTokenParams = { audience: 'https://api.example.com' };
(empty)

Mock Server Attributes 5

AttributeDescription and allowed valuesDefault
mock-server

truefalse

Enables the built-in, zero-dependency in-browser mock server. Transparently intercepts outgoing network requests (both RapiDoc's Try console and host application fetch/XHR calls) and serves mock responses based on OpenAPI examples or generated from schemas.
false
mock-server-status-code
HTTP status code to answer with, or several separated by commas, used in turn per operation (503, 503, 200: two failures, then a success); a random: prefix picks one at random for each call (random:200, 500), cycle: says in turn explicitly. Or a JSON map by operation, each with its own codes and prefix ({ "POST /orders": "cycle:503, 200", "*": "200" }). Set it to an empty string to use the first 2xx response in the spec.
200
mock-server-status-strategy

firstcyclerandom

Deprecated: put the strategy in front of the codes in mock-server-status-code instead (random:200, 500). How codes without a prefix are picked: 'cycle' uses them in turn per operation (the default); 'random' picks one for each call; 'first' always answers the first code, the same as giving only that code.
cycle
mock-server-delay
Simulated network latency in milliseconds before resolving mock responses. Useful for testing client loading spinners and optimistic UI updates. For a streamed response (OpenAPI 3.2 itemSchema: Server-Sent Events, JSON Lines), the response starts at once and this is the gap between its items (300 ms when 0).
0
mock-server-log

truefalse

Logs one line per answered request (method, path and status code) to the browser console.
false
